1. Critical Bug: Case-Sensitivity Errors in GlobalsIn Kustom, global variable keys are strictly case-sensitive. Your JSON defines the keys in lowercase, but your formulas alternate casing, which will cause Kustom to return empty values or errors.total vs Total: Your global identifier key is "total" (lowercase). However, in the formulas for rows, r1c, and r2c, you call gv(Total) with a capital T.Fix: Change all instances of gv(Total) to gv(total) inside those three global text formulas.icon_vis vs Icon_Vis: Your global key is defined as "icon_vis". In the shape backgrounds, font icons, and text labels across all 8 squares, your formulas call gv(Icon_Vis).Fix: Change gv(Icon_Vis) to gv(icon_vis) everywhere to prevent icon visibility toggles and font padding from breaking.2. Architectural Recommendation: Prevent "Global Explosion"You mentioned leaving indices 29–49 as placeholders to copy over to the other globals. If you populate all 8 sub-slots for all 8 apps with independent global variables (ht, hi, hicon), you will end up with:$$\text{(8 Apps)} \times \text{(8 sub-slots)} \times \text{(3 variables per slot)} = 192 \text{ variables}$$Plus your core variables, that is over 216 global variables. Managing this in the Kustom editor will severely lag the app, bloat your file size, and make re-ordering apps an absolute nightmare.The Solution: Use String ArraysInstead of dozens of separate globals, turn each app's profile into a single Text global containing a delimiter-separated array string.For example, change app1 to a single Text global named app1_data with a value formatted like this:MainTitle,MainIntent,MainIcon|Sub1Title,Sub1Intent,Sub1Icon|Sub2Title,Sub2Intent,Sub2Icon...For your Firefox setup, the value of app1_data would look like:PlaintextFirefox,intent://firefox,brand-firefox|Back,0,arrow-left|||||||
(Where each pipe | corresponds to the active index state).You can then extract your values smoothly in a single line using nested tc(split) formulas:To get the Title: $tc(split, tc(split, gv(app1_data), "|", gv(active)), ",", 0)$To get the Intent: $tc(split, tc(split, gv(app1_data), "|", gv(active)), ",", 1)$To get the Icon: $tc(split, tc(split, gv(app1_data), "|", gv(active)), ",", 2)$This reduces your global variable count from 216 down to just 8 text globals (one per square), making your komponent lightweight and incredibly easy to edit.3. Visual Layout Issue: Mismatched Square Widths on Odd TotalsIn your background (bg) shape width formulas, you calculate sizing based on row-specific columns:Row 1 uses: $(gv(totalw) / gv(R1_Cols)) - gv(Gutter)$Row 2 uses: $(gv(totalw) / gv(R2_Cols)) - gv(Gutter)$When total = 5, R1_Cols evaluates to 3 and R2_Cols evaluates to 2. This means your Row 1 squares will be 240px wide ($720 / 3$) and your Row 2 squares will be 360px wide ($720 / 2$). The rows will look completely misaligned.Fix: If you want a uniform grid alignment where all squares remain the exact same size regardless of the row they occupy, base the width on the maximum potential columns (4) when total exceeds 4:Plaintext$gv(totalw) / if(gv(total) <= 4, gv(total), 4) - gv(Gutter)$
4. Syntax Error in Max_WdthYour formula for Max_Wdth is formatted as:Plaintext"$(gv(totalw) / if(gv(total) < 4, gv(total), 4)) - 24$"
Starting a Kustom formula block with $( instead of just $ can throw parser exceptions or break evaluations in several older and newer builds of Kustom.Fix: Strip out the outer wrapping parentheses:Plaintext$gv(totalw) / if(gv(total) < 4, gv(total), 4) - 24$

"action": "SWITCH_GLOBAL",

This changes the visual states (active changes from 0 to 1, etc.), but it doesn't actually launch an application or run an intent shortcut.To make your taskbar functional, you need to add a second touch entry to your action items or structure a conditional event. If you use the String Array method suggested above, you can add an Open Link or Launch Shortcut action linked to a formula that monitors your intent string:Plaintext$if(gv(active) = 0, "", tc(split, tc(split, gv(tc(reg, "appActive_data", "Active", gv(active))), "|", gv(active)), ",", 1))$
(This ensures that if a user taps an item while active = 0, it opens the menu, but if they tap it while an intent value exists, it runs the intent).6.
